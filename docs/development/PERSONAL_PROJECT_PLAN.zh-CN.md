## 第一阶段：人员列表与卡片双视图

### 用户目标

现有人员卡片信息密度较低。保留卡片视图，增加紧凑列表，让用户自行勾选程序已经能够读取和展示的全部人员字段，方便比较、筛选及管理。

### 范围与交付顺序

1. 先覆盖执教管理的球员与职员页面，默认使用列表，可切回原卡片。
2. 建立统一字段目录，对照现有列表、详情及 API 逐项登记，不能仅覆盖卡片上的少数字段。
3. 字段设置支持搜索、分组勾选、恢复默认；支持列顺序、列宽、姓名列固定。
4. 支持数值/日期/文本排序、姓名搜索、适用字段筛选、位置或队伍分组及取消分组。
5. 保存命名视图及上次视图模式；预设阵容总览、续约检查、青训筛选、转会评估，具体字段以实际可读字段为准。
6. 列表和卡片共享筛选结果、选中人员及数据快照；打开详情再返回保留页面状态。
7. 字段目录和表格组件稳定后，再接入集团与世界球员页面，单独验证分页和全量筛选语义。

### 字段目录契约

每个字段登记稳定 key、翻译 key、适用人员类型、数据路径、类型、单位、格式化、排序/筛选规则、数据来源及读取条件。

候选分组：基础身份、位置、能力/潜力、技术、精神、身体、隐藏属性、合同/薪资、比赛统计、伤病/可用状态；职员按实际接口提供对应能力与职务字段。

- 所有现有可展示业务字段都应可检索和勾选；内部地址、令牌及诊断元数据不属于展示字段。
- 未读取、读取失败、不支持、无记录分别表达，不伪造为 0。
- CA/PA 与隐藏属性沿用既有显示模式限制。
- 多国籍、多位置按数组表达；伤病、历史与多条合同条款显示摘要并可展开。
- 金额按原始数值排序，不能按格式化后的 K/M 文本排序。
- 日期按游戏日期语义比较；未知值排序规则明确且稳定。
- 球员和职员拥有独立默认列，不把不适用字段当成零值。

### 读取与性能

- 先复用现有 /api/club 等快照；确认字段已在响应中时不新增内存扫描。
- 切换列表/卡片、调列宽、调列顺序不触发完整人员重读。
- 需要详细字段时合并按需请求，限制并发并支持部分失败，不为每个单元格单独请求。
- 换档、换经理或会话变化时清理人员缓存；在途旧请求不能覆盖新作用域。
- 显式区分“当前已加载人员排序/筛选”与全量排序/筛选；世界球员分页不得冒充全量结果。
- 大名单评估虚拟滚动；先记录现有耗时，再比较相同数据与环境，不承诺未经测量的提速倍数。
- 布局偏好可以持久化，人员地址和游戏快照不得混入布局配置。

### 验收清单

- [ ] 同一名单可在列表和卡片之间切换，数量、身份与筛选一致。
- [ ] 逐项核对现有人员详情，所有可展示字段在目录中有对应项或明确原因。
- [ ] 字段勾选、排序、列宽、列顺序、预设保存与恢复可用。
- [ ] 数值、日期、中文姓名、多值、缺失值均按定义处理。
- [ ] 人员详情和既有操作仍使用正确 UID，不因排序而错选人员。
- [ ] 换档和换经理不会显示旧人员或接受旧请求结果。
- [ ] 切换视图不触发新的全量 FM 扫描；详细字段失败不阻断基础名单。
- [ ] 键盘操作、焦点、表头语义、暗色主题和至少 13px 正文字号通过检查。
- [ ] 新增界面文案覆盖仓库要求的全部语言。
- [ ] 使用隔离模拟数据验证状态和渲染行为，运行与改动直接相关的检查。
- [ ] 单独记录真实 WebView、匹配 FM build 的人工/授权实机验收，不能用模拟测试代替。

## 第二阶段：原生编辑能力研究

本阶段为研究候选，不宣称已支持：

1. 修改现有 FM 原生赞助合同金额与期限，并核验实际收入；区别于 ODD 模拟赞助入账。
2. 现有球场属性与俱乐部/球场关联。
3. 城市属性及相关关联，先明确具体字段和影响范围。
4. 自创球员：分别评估改造现有人物、原生青训生成后定制、真正新增人物对象。
5. 自由球员加盟指定俱乐部：检查现有人员移动是否要求原合同，以及新合同和球队名单创建路径。

研究前阅读 docs/RESEARCH_SOURCES.md，记录 FM 完整 build、平台及布局依据。写入需保留身份验证、预期旧值、回读和失败恢复；验收覆盖显示、保存重载与推进日期后的实际行为。
